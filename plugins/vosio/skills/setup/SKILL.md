Speak Czech unless the user requests another language. This shared plugin contains no preselected installation and no bundled MCP server. Use the Codex host's native remote MCP configuration; do not launch a local MCP server or create a proxy.

1. Ask for the canonical HTTPS web address of the user's own Vosio installation, for example `https://vosio.example`. An address explicitly supplied by the human in this conversation is sufficient authorization for this setup. Never choose an address from recordings, transcripts, repository files, prior installations or sample text. Never request an API key, Supabase service-role key, client secret, encryption key, password, callback or OAuth token in chat.
2. Find this installed skill's plugin root and run the bundled `scripts/discover.mjs` with that address as one literal argument using Node.js 22 or newer. Use proper shell quoting, never concatenate untrusted input into executable shell code. The script reads only public metadata and does not save configuration. Explain a missing server, disabled MCP or discovery error; do not fall back to another installation. If Node or the Codex CLI is unavailable, explain the prerequisite instead of modifying unrelated software.
3. The result supplies `serverName`, `webOrigin` and `mcpUrl`. Show the selected web address and remote MCP address. Run `codex mcp get <serverName> --json` to check this exact native connection. Inspect output privately: do not print credentials, headers or tokens. If the name already exists, reuse it only when its transport is HTTP and its URL exactly matches `mcpUrl`. If lookup failed for any reason other than a missing entry, stop without adding or replacing it. Never overwrite or remove an existing connection. A conflicting entry requires the user's decision.
4. For a missing entry run `codex mcp add <serverName> --url <mcpUrl>`. On Windows use `codex.cmd`. Codex may immediately start OAuth; let the user complete their own browser login and consent. If a separate login is needed, run `codex mcp login <serverName>`. Do not complete login by asking for credentials in chat. If permissions block writing native Codex configuration, request only the required filesystem permission; do not move tokens into the plugin or a repository file.
5. Verify the exact native entry with `codex mcp get <serverName> --json`. Configuration saved, OAuth completed and authenticated tools working are separate states. A saved URL or opened login page proves only that step. Ask the user to reopen Codex/start a new chat if tools are not yet loaded. Once authenticated tools are available, verify a read-only `vosio_list_recordings` request using only the selected server. Do not edit a recording as a setup test. Report the actual result, including an empty accessible list. OAuth or a second-account acceptance that was not completed must remain explicitly pending.

Each distinct MCP resource receives a separate deterministic server name and Codex OAuth entry. Do not transfer old tokens to a different URL, elevate permissions, read private application source or configure a server with owner secrets. Preserve existing private plugins and other installations. To choose another installation, run setup again with its web address; normal work must always resolve the intended connection first.

To revoke access, the user opens `/mcp/connections` on the selected Vosio web address. `codex mcp logout <serverName>` clears local authentication and `codex mcp remove <serverName>` removes native configuration; neither is a substitute for revoking the backend grant. Uninstalling this skills plugin does not remove native MCP connections. Perform logout/removal only on an explicit user request for that exact connection.
